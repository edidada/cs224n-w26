# A4 LLM Evals：实现进度与验收边界

来源为仓库导入的 Stanford CS224n Winter 2026 官方 A4 starter；该仓库是归档镜像，不是官方 Git fork。

本分支目前补全 GSM8K 标准 A/B、改进提示 A 的全 100 题评测入口。官方标准提示与提取器保留；使用十进制数值比较，无法解析或非有限值计错，分母包含全部题目。逐次保存问题、提示、原始响应、令牌与费用、预期答案和判定，异常会中止并保留已完成记录。输出独占创建，已有记录不会被覆盖；暂不支持断点续跑，不能删除记录盲目重试以免重复计费。

Alpaca E/F/Z 全30组调用、逐次原始请求/响应保存和胜率统计已实现；矛盾、重复或缺失标签单独计为 invalid，与有效平局区分，二者均保留在30题胜率分母内。每次响应立即落盘，即使后续调用失败也能保留 E/F 原文。长度图共用直方图边界，单位为按空白划分的词数，不冒充 provider token；平局和无效组排除并标注数量，因此可能不足30个胜负样本，不伪造偏好。

尚未完成：Alpaca E/F/Z 真实全量执行、人工核对 5 条及真实分歧、真实长度图；GSM8K 实际分数与比较图、改进是否成立；G/H/I 合成密码红队实验及失败策略。没有真实 API 结果，没有宣称提示词改善分数。

真实运行需要用户提供的 GCP 项目、ADC 身份、STUDENT_EMAIL 和明确费用预算。本轮未调用 Vertex，未产生云端评测费用。官方客户端保持原样。独立 a4-llm-evals.yml 在远端使用明确标记的假客户端检查100题计分/无效计错、30组原始记录/裁判标签、绘图及已有输出保护；这只验证协议流程，不构成实验验收。禁止根据客户端秘密生成逻辑伪造红队成功。
